NOTA — BLINDAJE A NIVEL BASE DE DATOS (opcional, para más adelante)
═══════════════════════════════════════════════════════════════════

Mientras RLS siga desactivado, cualquier cliente con la anon key
podría hacer INSERT directo a movimientos saltándose el frontend.
Cuando reactivemos RLS, conviene agregar este trigger en Supabase:

  CREATE OR REPLACE FUNCTION bloquear_mov_liquidado()
  RETURNS TRIGGER AS $$
  BEGIN
    IF EXISTS (
      SELECT 1 FROM contratos_tycoon
      WHERE id = NEW.contrato_id AND estado = 'Liquidado'
    ) THEN
      RAISE EXCEPTION 'Contrato liquidado — no admite movimientos';
    END IF;
    RETURN NEW;
  END;
  $$ LANGUAGE plpgsql;

  CREATE TRIGGER trg_bloquear_mov_liquidado
  BEFORE INSERT ON movimientos
  FOR EACH ROW EXECUTE FUNCTION bloquear_mov_liquidado();
